\textbf{How much is missing.} The union of both static graphs contains a median of
\edgeUnionMed{} of the observed calls per repository, from \edgeUnionMin{} to \edgeUnionMax{}.
Pyright alone reaches \edgePyrightMed{} and PyCG \edgePycgMed{}; Pyright finds more of the
observed calls in \nPyrightBeatsPycg{} of \nRuntimeRepos{} repositories (Fig.~\ref{fig:recall}a), so in
this corpus the type checker is the stronger call-graph source. Pooled over \nItems{} call-resolution items
(\nRealItems{} of them observed calls), the union has precision \itemUnionP{} and recall
\itemUnionR{} (PyCG \itemPycgP/\itemPycgR, Pyright \itemPyrightP/\itemPyrightR). Plain name
matching, which treats every name on an executed line as a call, has precision \itemNameP{}: most
names in code that ran are not calls the tests made. Union precision is \staticPrecUniqueCall{} on
calls to uniquely named functions and \staticPrecSharedCall{} on shared names, where an unobserved
claim may be a call that another run would make.

\textbf{Where it misses.} Of the \nMissed{} observed calls the union misses, \pctMissShared{} go
to a method whose name is shared by several functions in the package, that is, dispatch over a
class hierarchy or over unrelated classes with a common method name, and \pctMissReference{} are
names written without call syntax, such as property reads and functions passed as values. The
worst repository illustrates the first pattern: \texttt{ShivyC}, a C compiler, defines
\texttt{make\_il} on \shivycMakeIl{} syntax-tree classes and \texttt{make\_asm} on \shivycMakeAsm, and the static union
holds fewer than half of its observed calls. A further \nUnnamed{} observed calls
(\pctUnnamed{} of all calls) reach a function never named in the calling function, so no resolver
that reads the caller's code can find them: \pctUnnamedDunder{} are special methods invoked
implicitly (operators, iteration, attribute hooks), and the rest are callbacks and functions reached
through library code, \pctUnnamedTopOfRest{} of them in one repository, \texttt{\unnamedTopRepo}. Implicit calls also
explain the lowest recall in Table~\ref{tab:recall}: \texttt{python-lazy-object-proxy} (\edgeUnionMin)
is a proxy-object library whose tests exercise operator overloading, so almost every observed call
is a special method that no call site names.

\textbf{Dynamism predicts recall only weakly.} The corpus was stratified by an AST score of
reflective and dynamic constructs, but across repositories the score and union recall correlate
only weakly (Spearman $\rho = \densitySpearman$, Fig.~\ref{fig:recall}b), and median recall is not ordered by stratum:
\edgeMedLow{} for LOW, \edgeMedMed{} for MED and \edgeMedHigh{} for HIGH. The constructs such scores
count, reflection and dynamic imports, are not where static analysers lose most calls on real code;
ordinary polymorphic dispatch is.

\textbf{Coverage and stability of the labels.} The tests executed a median of \covMed{} of each
package's statement lines (\covMin{} to \covMax{}). Recall does not rise with coverage (Spearman
$\rho = \covSpearman$ across repositories) or with the number of tests ($\rho = \testsSpearman$);
if anything, more thorough suites expose more of the hard calls. \retraceSentence{}

Table~\ref{tab:llm} compares the LLMs with the static union on the sampled callers, which are
enriched for hard items. Every LLM finds more of the observed calls than static analysis does:
recall rises from \llmTwentyStaticR{} for the static union on the same items to \llmTwentyR{} for gpt-oss-20b, \llmOneTwentyR{} for gpt-oss-120b and \llmQwenR{} for qwen3.8-27b.
Precision falls from \llmTwentyStaticP{} to between \llmOneTwentyP{} and \llmQwenP: the models claim calls

On real code, then, the micro-benchmark finding that PyCG outperforms LLMs~\cite{venkatesh2025llmcg}
holds for precision but reverses for recall. Resampling whole repositories, the 95\% interval for
recall is \ciOneTwentyRec{} for gpt-oss-120b against \ciStaticRec{} for the static union, but the F1
intervals overlap (\ciOneTwentyFone{} against \ciStaticFone{}), and an LLM has the higher F1 in only
\llmBeatsMin--\llmBeatsMax{} of \llmReposN{} repositories.

missed they recover \compMissedR{}, and on those it found they agree on \compFoundR{}.

The bottom of Table~\ref{tab:llm} scores every resolver on the same items, leaving one whole
repository out at a time. Adding every LLM claim to the static graph maximises recall at a large
cost in precision. A majority vote of the three LLMs matches the static union on F1
(\loroMajorityFone{} against \loroUnionFone). The learned combiner, trained on \nCombItems{} items
from \nCombRepos{} repositories, gives every source a positive weight and discounts names written
without call syntax; on a repository it has never seen it reaches F1 \loroCombFone{} (precision
\loroCombP, recall \loroCombR, against \loroUnionP{} and \loroUnionR{} for the union). It beats the
union on \nLoroBeats{} of \nLoroRepos{} repositories and loses on \nLoroWorse. With folds grouped by
caller, which lets it train on other functions of the test project, it reaches \cvCombFone{}, no
better: what it learns is not specific to one project.}

\renewcommand{\rqDiscussionLlm}{Static analysis is precise but blind to dispatch over shared
names and to references; the LLMs see those but over-claim. Neither is enough alone, and combined
through a filter learned on other projects they beat static analysis on unseen code. A tool that
consumes call graphs can treat LLM answers as a second vote, not as a replacement.}

\renewcommand{\rqConclusion}{the union of two static analysers finds a median of \edgeUnionMed{} of
the calls, and its misses concentrate on shared method names rather than on the reflective
constructs usually blamed. LLMs recover many of those calls at a cost in precision, and a learned
combination of the two, trained on other projects, improves on static analysis alone.}
